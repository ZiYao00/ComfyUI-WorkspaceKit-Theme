# WK 主题面板编辑器重构计划

> 状态：进行中；UI 骨架、工具条、元数据、参考图导入与推荐色板已完成。
> 更新：2026-08-03
> 适用项目：`ComfyUI-WorkspaceKit-Theme`

## 1. 目的与边界

本文件记录 WK 主题面板后续的界面和交互重构决定。后续实施必须按小批次完成，并分别在两种模式下验收：

- 独立模式：未安装或关闭 WorkspaceKit 标签合并时；
- 合并模式：作为 WorkspaceKit 的 `WK 主题`标签时。

目标不是增加第二套界面，而是让 Theme 和 WK 工作流、WK 节点、WK 模板、WK 版式共用同一套 WK 设计语言；Theme 仍能独立使用。本文是后续 Theme 功能批次的当前依据，不改变现有主题数据，除非对应批次另行记录兼容与回退方案。

## 2. 已确认的问题

以下结论来自当前源码和 2026-08-01 的界面截图对照，而非猜测。

1. 独立模式没有稳定使用与 Layout 相同的顶部壳层，视觉上缺少 `[🎨 WK Theme] [设置]` 的统一入口。
2. Theme 的自定义控制条覆盖了共享控制条的布局规则，导致搜索框和图标按钮间距异常；标题状态也没有遵守“左标题、右状态”的标准布局。
3. 参考图画布即使未载入内容仍可能占据大面积虚线区域。源码中 `canvas.hidden = true` 与 CSS 的 `display: block` 存在冲突风险。
4. 主题文件读取、当前界面读取、应用、恢复、导出、退出等操作混在同一排或同一个不稳定菜单中，首屏缺少明确主任务。
5. 当前更多菜单把菜单内容插入按钮内部，并叠加了多个点击监听，属于不稳定的 Popover 结构；这也是下拉菜单无法稳定打开的优先排查点。
6. 现有英文/中文混用（例如 `Theme Lab`、`REFERENCE COLORS`）仍未完成完整国际化。

## 3. 目标页面结构

Theme 采用与 WK 其它标签相同的五段结构；参考图和卡片参数属于内容区的功能分区，不单独创造新的页面壳层。

```text
┌─────────────────────────────────────────────┐
│ [ 🎨 WK Theme ]                         [⚙] │  独立模式顶部壳层
├─────────────────────────────────────────────┤
│ Theme Lab                    当前主题：未载入 │  标题左、状态右
├─────────────────────────────────────────────┤
│ [ 搜索主题参数 …………………… ] [撤销] [重做] [···] │  已载入时的控制条
├─────────────────────────────────────────────┤
│ 文件读取 / 参考图取色（可选） / 卡片参数      │  内容区
└─────────────────────────────────────────────┘
```

### 3.1 未载入主题时

未载入主题时，卡片参数区不显示空的大表单，而显示明确的两个主操作：

```text
┌─────────────────────────────────────────────┐
│ [ 导入主题 ]       [ 读取当前主题 ]          │
└─────────────────────────────────────────────┘
```

成功导入或读取后，这两个大按钮隐藏，改为显示文件元数据和主题参数卡片。

### 3.2 已载入主题时

文件读取控制条固定为一行：

```text
[ 选择主题……………… ▾ ] [↻] [↓ 导入] [◎ 读取当前主题]
```

- 使用 CSS Grid：`minmax(0, 1fr) auto auto auto`；
- 只有“选择主题”可压缩，并以省略号显示长名称；
- 刷新、导入、读取当前主题始终保持可点击尺寸和单行；
- 禁止因为窄宽度自动折成两行。

主题载入后，上方主控制条以搜索、撤销、重做、更多为主；导出、恢复、退出等低频动作放入“更多”。

## 4. 主题文件库

第一阶段不读取 ComfyUI 客户端主题目录，也不扫描用户磁盘。主题文件只放在插件自身目录：

```text
js/themes/
  manifest.json
  comfyui-default/     # 插件随附的官方默认主题副本，只读
  wk/                  # WK 主题，允许后续保存和另存为
```

- `examples/ZY_02.json`可作为首个 WK 主题的来源，但必须同时修改显示名称和唯一 `id`，不能只改名称；
- `manifest.json`显式列出可选主题及分组，浏览器只请求清单，不枚举目录。由于 Theme 是纯前端插件，静态资源必须位于 `js/` 的 Web 目录内；
- `[↻]`在第一阶段只重新读取 `manifest.json`；用户手工增加文件后，需要同时维护清单；
- 未来如需自动发现新增文件，再单独设计服务端扫描接口，不能在前端猜测文件系统。

## 5. 卡片参数区的文件元数据

不使用复杂的“另存为”弹窗。主题成功载入后，在卡片参数区顶部提供单行元数据：

```text
文件名 [ wk-dark-zy        ] .json   主题名 [ WK Dark ZY ]   ID [ wk-dark-zy ]
```

- 文件名输入框不包含固定的 `.json` 后缀；
- 主题名是用户可读名称，可以使用中文；
- ID 是机器标识，默认从文件名生成；用户手动改过 ID 后，不再被文件名自动覆盖；
- 元数据只影响保存目标，不应中断当前的实时预览；
- 官方默认主题、外部导入和“读取当前主题”均默认创建 WK 副本，不能直接覆盖官方副本。

保存规则将在具备服务端写入接口后生效：

| 当前来源 | 元数据变化 | 保存结果 |
| --- | --- | --- |
| 官方默认 / 外部导入 / 当前界面读取 | 任意 | 新建到 `themes/wk/` |
| 已载入 WK 主题 | 文件名与 ID 未变 | 覆盖前确认 |
| 已载入 WK 主题 | 文件名或 ID 已变 | 作为新副本保存 |

## 6. 编辑、保存和退出语义

主题会话需明确记录 `sourceType`、`sourceFile`、`dirty` 和打开 Theme 前的运行时快照。这样“保存”和“退出”才有真实、可预测的语义。

- 实时预览：固定为默认行为，不再单独放一个开关；
- 应用主题：在实时预览恒定开启后属重复操作，应从首要按钮中移除；
- 撤销/重做：保留为常用按钮。当前历史上限是 80 个完整主题快照，滑块仅在松开时提交一个历史点；
- 单字段恢复：保留，恢复到载入基线；
- 恢复载入主题：放到“更多”，恢复整个编辑主题到载入基线；
- 打开前界面快照：不再作为独立菜单动作，只供“退出编辑”使用，防止编辑器状态与实际界面外观不一致。

### 6.1 退出编辑

点击后如存在未保存变化，显示确认提示；确认后恢复打开 Theme 前的运行时主题快照，并清除本次会话的主题、历史、搜索和卡片显示。

### 6.2 保存并退出

此动作必须在真正支持写入 `themes/wk/` 后才开放。保存/覆盖完成并得到服务端成功结果后，才退出编辑；失败时保持编辑器和当前预览不变。它不能用浏览器下载伪装成“保存”。

## 7. Popover、参考图与样式边界

### 7.1 更多菜单

菜单应是按钮旁的同级浮层，由单一开关处理打开、关闭、Esc 与点击外部关闭；禁止把菜单 DOM 放入 `<button>` 内，也不要给同一动作叠加多个 click 监听。

建议菜单内容：

```text
导入主题
读取当前主题
导出 JSON
恢复载入主题
──────────
保存 / 保存副本
退出编辑 / 保存并退出
```

### 7.2 参考图

- “参考图取色”默认折叠，是可选能力，不能抢占首次进入的首屏；
- 只有实际存在图片时才显示画布和取色内容；
- CSS 必须尊重 `[hidden]`，例如用 `.wkt-reference-canvas:not([hidden]) { display: block; }`，不能用无条件 `display: block` 覆盖隐藏状态；
- 空状态不得留下大面积虚线画布。

### 7.3 共享 UI 边界

- 独立模式使用 WorkspaceKit UI Vendor 的 `createStandaloneShell()`；
- 合并模式只使用宿主提供的标准区域，不改写宿主根节点或其它插件区域；
- 自定义样式应限制在 Theme 自身根容器，不对 `workspace2-shell`、共享工具条等宿主元素写宽高、背景、Flex 覆盖；
- 标题状态沿用共享的右侧状态区域；控制条不覆盖共享 `workspacekit-ui-control-row` 的布局定义。

## 8. 国际化

本轮优先完成结构与行为。完成后将 Theme 所有用户可见文本纳入现有 i18n 表：标题、状态、菜单、空状态、字段名、确认提示和错误提示都必须提供中文与英文。禁止在组件中再硬编码 `Theme Lab`、`REFERENCE COLORS` 等展示文本。

## 9. 分批实施顺序

每批只改一个明确目标；每批通过静态检查和真实页面验收后才进入下一批。若同一批连续两次无法定位问题，应回退该批并复盘，而不是继续叠加补丁。

1. **P0：页面骨架与稳定菜单**
   - 独立模式接入标准 WK 顶部壳层；
   - 修正标题/控制条共享布局；
   - 重建更多菜单 Popover；
   - 修复参考图 `[hidden]` 空白占位。
2. **P1：首屏任务与本地主题清单**
   - 未载入主题的“导入 / 读取当前主题”主操作；
   - 单行文件读取控制条；
   - 新增 `themes/manifest.json` 与两个内置主题目录；
   - 静态主题选择与刷新清单。
3. **P2-4A：会话来源、脏状态与元数据**
   - 卡片参数区的文件名、主题名、ID；
   - `sourceType`、`sourceFile`、`dirty` 与元数据基线；
   - 仅前端状态，不写入磁盘。
4. **P2-4B：受控保存服务**
   - 仅允许写入 `js/themes/wk/`；
   - 文件名和 JSON 校验、原子写入、覆盖前自动备份；
   - 新副本同步更新 `manifest.json`。
5. **P2-4C：保存与退出 UI**
   - 保存、保存副本、退出编辑、保存并退出；
   - 覆盖确认、未保存提示、失败保护。
6. **P3：参考图、字段密度与完整双语**
   - P3-1：参考图折叠区与图片状态保留；
   - P3-2：参数卡片的紧凑布局；
   - P3-3：全量中英文与提示语检查。
